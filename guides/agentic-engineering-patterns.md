# Agentic Engineering Patterns

> **Fetched**: 2026-03-05
> **Archived**: 2026-03-05

A comprehensive guide to professional practices for developers working with coding agents like Claude Code. Distinguishes structured "agentic engineering" from casual "vibe coding" by emphasizing methodology applied by experienced engineers to amplify their capabilities.

---

## Principles

### Writing Code Is Cheap Now

The fundamental shift: code generation costs have dropped dramatically. Producing hundreds of lines of quality code used to require a full day — coding agents now do it in minutes. This disrupts traditional decision-making frameworks built around expensive code production.

**Good code still costs.** While generation is nearly free, delivering *good code* requires meeting nine criteria:

1. Functions as intended without bugs
2. Verifiable fitness for purpose
3. Solves the right problem
4. Handles error cases gracefully with informative messages
5. Simple, minimal design understandable by humans and machines
6. Protected by regression test suites
7. Current, accurate documentation
8. Future-change-friendly design (maintaining YAGNI principles)
9. Appropriate non-functional qualities (accessibility, security, reliability)

**Building new habits**: Override cost-avoidance instincts by running asynchronous agent sessions for ideas previously dismissed as uneconomical. Low-cost tokens make experimental implementation viable.

### Hoard Things You Know How to Do

Build a personal collection of working code examples and solutions. This becomes especially powerful when working with coding agents.

> "A big part of the skill in building software is understanding what's possible and what isn't, and having at least a rough idea of how those things can be accomplished."

**Hoarding methods:**
- Blog posts and TIL notes documenting discovered techniques
- GitHub repositories containing proof-of-concepts and project code
- Tool collections (e.g., tools.simonwillison.net)
- Research repositories with agent-generated code and analysis

**Recombination strategy**: The most powerful technique is telling agents to "build something new by combining two or more existing working examples." Example: combining Tesseract.js (OCR) + PDF.js into a single drag-and-drop PDF OCR tool.

> "Coding agents mean we only ever need to figure out a useful trick once."

### Anti-patterns: Things to Avoid

**Primary anti-pattern: Filing PRs with unreviewed agent-generated code.**

This practice delegates actual work to reviewers who could have prompted an agent themselves.

**Four traits of quality agent-generated PRs:**

1. **Functionality** — Code works reliably; developer has confidence in its operation
2. **Size** — Changes are reviewable without excessive cognitive burden; prefer multiple smaller PRs
3. **Context** — Higher-level goals, relevant issue links, and specifications accompany changes
4. **Description quality** — PR descriptions generated by agents require author validation before submission

**Demonstrate due diligence**: Include manual testing notes, implementation choice comments, screenshots, or feature videos.

## Testing and QA

### Red/Green TDD

A concise four-word directive: **"Use red/green TDD"** — shorthand for implementing test-driven development with agents.

**Why it works for coding agents:**
- Prevents non-functional code (agents might write code that doesn't work)
- Avoids unnecessary code (agents might build unused features)
- Creates a robust automated test suite protecting against future regressions

**The red/green cycle:**
- **Red phase**: Write tests first, verify they fail
- **Green phase**: Develop implementation until tests pass

Confirming test failure first is critical — skipping this step risks creating tests that already pass, failing to validate the new implementation.

**Example prompt**: "Build a Python function to extract headers from a markdown string. Use red/green TDD."

### First Run the Tests

Run tests as the **first action** when beginning a new agent session on an existing project.

**Simple prompt**: "First run the tests" (or "Run 'uv run pytest'")

**Three key purposes:**
1. **Discovery and future automation** — Forces the agent to locate and understand test infrastructure
2. **Project complexity signals** — Test output reveals approximate project size and complexity
3. **Mental framework shift** — Establishes a testing mindset, encouraging expanded test coverage

Agents already lean toward testing practices. Existing test suites amplify this inclination, nearly guaranteeing validation of new modifications.

## Understanding Code

### Linear Walkthroughs

Use coding agents to generate structured walkthroughs of codebases — helpful for understanding existing projects, forgotten code, or vibe-coded applications.

**Prompt pattern**: "Read the source and then plan a linear walkthrough of the code that explains how it all works in detail."

**Key tool**: Showboat — an agent documentation utility supporting:
- `showboat note` — adds Markdown commentary
- `showboat exec` — executes commands and embeds output

Use `sed`, `grep`, and `cat` for including code snippets rather than manual copying — this avoids hallucinations through direct code extraction.

### Interactive Explanations

Address "cognitive debt" from incomprehensible AI-generated code by building **interactive explanations**.

**Example**: An animated word cloud visualization tool that:
- Accepts text input (persisted via URL fragments)
- Animates word placement step-by-step
- Shows collision detection boxes
- Includes playback controls (pause, speed, frame-by-frame)
- Allows PNG downloads at any stage

**Process**: Initial code generation → linear walkthrough → animated explanation for intuitive algorithmic understanding.

> "A good coding agent can produce these on demand to help explain code — its own code or code written by others."

## Annotated Prompts

### GIF Optimization Tool (WebAssembly + Gifsicle)

A case study in prompt engineering for complex agent tasks.

**Key prompt elements:**
- **File declaration** — Simply stating a filename establishes the creation target
- **WASM compilation** — "Compile gifsicle to WASM" delegates complex toolchain work (Emscripten) to the agent
- **UI patterns** — Drag-and-drop is "almost free" when articulated to an agent
- **Trust agent judgment** — "I didn't bother defining the collection of settings I wanted — Claude has good enough taste at picking those for me"

**Testing strategy**: Agents work much better when they can test their code during development. Use browser automation tools with agent-focused help documentation.

**Follow-up refinements**: Build scripts that clone dependencies temporarily, WASM bundle inclusion for deployment, attribution.

## Appendix: Prompts I Use

### Artifacts Custom Instructions (for prototyping HTML/JS tools)

- No React — always plain HTML, vanilla JavaScript, and CSS with minimal dependencies
- CSS: two-space indentation, starting with universal box-sizing
- Input/textarea elements: 16px font size
- Font: Helvetica
- JavaScript: two-space indentation, module-type script tags
- Heading style: sentence case

### Proofreading Prompt

> "You are a proofreader for posts about to be published."

Six responsibilities: spelling/typos, grammar errors, repetitive phrasing, logical/factual errors, weak arguments, broken/placeholder links.

### Editorial Philosophy

> "I don't let LLMs write text for my blog." Content expressing opinions or using first-person pronouns must be author-written. LLMs assist with code documentation and proofreading only.
